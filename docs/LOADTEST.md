# Навантажувальне тестування

Інструмент — [Locust](https://locust.io) (Python). Сценарій — `loadtest/locustfile.py`.

## Запуск

```bash
pip install -r loadtest/requirements.txt
./loadtest/run.sh http://<адреса-ALB> <назва-прогону>
```

`terraform output -raw app_url` у `terraform/app` дає адресу. Скрипт запускає Locust без вебінтерфейсу,
зберігає CSV у `loadtest/results/<назва-прогону>_*.csv` і друкує підсумок.

| Змінна | За замовчуванням | Зміст |
|---|---|---|
| `LT_USERS` | 60 | кількість віртуальних користувачів на сталій фазі (N) |
| `LT_RAMP_UP` | 120 | наростання від нуля до N, с |
| `LT_HOLD` | 300 | стала фаза, с |
| `LT_RAMP_DOWN` | 180 | спад до нуля, с |
| `LT_NO_CACHE` | не задано | `1` додає `Cache-Control: no-cache` і обходить кеш |

## Профіль «мало записів, багато читань»

Кожен віртуальний користувач при старті створює себе (`POST /users`), а потім у циклі виконує 10 операцій
з паузою 0.2–0.6 с між ними: 1 запис і 9 читань.

| № | Операція |
|---|---|
| 1 | `POST /posts` — створення поста |
| 2 | `GET /posts` — список |
| 3 | `GET /posts/{id}` — щойно створений пост |
| 4 | `GET /posts` |
| 5 | `GET /users/{id}` — дані автора |
| 6 | `GET /posts` |
| 7 | `GET /posts/{id}` — випадковий пост зі списку |
| 8 | `GET /users/{id}/posts` — пости автора |
| 9 | `GET /posts` |
| 10 | `GET /posts?offset=20` — друга сторінка |

Співвідношення читання до запису 9:1. Три фази: наростання 2 хв, стала фаза 5 хв, спад 3 хв (разом 10 хв).

## Чому N = 60

Один екземпляр (0.25 vCPU) обробляє близько 80 запитів за секунду. 60 користувачів з паузою 0.2–0.6 с
створюють попит, який у кілька разів перевищує цю потужність: CPU одного екземпляра доходить до 95 %,
спрацьовує масштабування й тривога. Пробний прогін зі 120 користувачами перевантажив єдиний екземпляр
так, що всі 15 з'єднань пулу SQLAlchemy були зайняті, а час відповіді сягав 50 с; тому для зразкового прогону
взято N = 60.
